# Researcher convenience tools

Use these tools only for the requested task. They operate on explicit local files, do not call a model or submission portal, and do not create scientific evidence or author approval. Run a tool's `--help` for its current contract. Use Python3.11 or later and new output directories outside the installed skill. Keep author profiles private and outside the distributed package.

## Continue research on another PC or conversation

`scripts/research_workspace.py checkpoint --root ROOT --state STATE_JSON --output-dir NEW` captures explicitly listed files, supplied decisions and next steps in a portable folder. Supply a state object with `project`, `question`, `decisions`, `next_steps`, `constraints`, `historical_counts`, and `files` as root-relative paths. Preserve actual historical counters as supplied facts; do not invent model totals or treat a saved limit as authorization for new calls. Select only needed material; never bundle credentials or an entire private account directory.

`resume --checkpoint CHECKPOINT_DIRECTORY` verifies the captured files and reads the saved context without running research or rewriting state. On another PC, copy the whole checkpoint folder and provide its path to the agent. A moved checkpoint must continue to use its internal relative paths. Missing or changed material is a reported problem, not permission to substitute another source or restart a study. The agent still needs to read the relevant actual sources, not just the continuation summary.

`scripts/environment_check.py --output-dir NEW [--pandoc EXISTING_ABSOLUTE_EXECUTABLE]` reports the current Python, installed document package versions, Pandoc probe, Windows PowerShell/Word registration and both retained template hashes. Run it from the installed skill with an output directory outside that skill. Exit0 means prerequisites were detected, Exit1 records missing or incompatible prerequisites, and Exit2 means invalid input or report failure. It does not install anything, launch Word, connect accounts or inspect credentials. Registration does not verify licensing or successful native rendering. An available Pandoc executable can replace the optional `pypandoc_binary` provider; final export still needs actual page and font checks.

## See current research status

`research_workspace.py status --root ROOT --state STATE_JSON --output-dir NEW` creates a compact Markdown summary and full JSON inventory. State has `project`, `question`, root-relative `current_manuscript`, `artifacts`, `remaining_tasks` and verbatim `historical_counts`. Each selected artifact has a distinct `id`, `role`, root-relative `path`, expected `sha256`, and optional `manuscript_sha256` identifying the actual manuscript it covers. Use actual records or original manifests for these bindings; do not label an old review as current by attaching today's manuscript hash.

Status distinguishes `current` (matching bytes and supplied manuscript binding), `stale` (another manuscript version), `changed`, `missing` and `unbound` (no manuscript association supplied). A source can properly be unbound. These states identify files and versions, not scientific quality, approval or acceptance. Reports are dated snapshots; run a new snapshot after files change rather than editing the earlier report. Preserve old scores with their reviewed hashes.

## Retain reusable primary-literature reading cards

`scripts/literature_cards.py prepare --root ROOT --cards CARDS_JSON --output-dir NEW` prepares source-bound notes. Supply `{cards: [...]}`; each card has `id`, `title`, `url`, `question`, `method`, `results`, `limitations`, `relevance`, `reading_scope`, `read_sections`, `unread_sections`, `source` and `witnesses`. The agent writes these fields from the actual reading, including unknowns. `reading_scope` is `full_body`, `selected_sections`, `abstract_only` or `metadata_only`. Identify what was and was not read; metadata and abstracts do not substitute for primary-body reading.

`source` records root-relative `path` and expected `sha256` for the retained original plus `text_path` and `text_sha256` for the text actually checked. A retained text source can use the same path/hash for both. Each witness has `start_line`, `end_line`, exact complete-line `quote`, and optional supplied `pages` locator. Page locators are not independently checked against PDF pages. The helper checks hashes and quotes, preserves mismatches and missing sources, and never certifies the interpretation, identity, novelty or reported completeness of reading. Exit1 means binding issues were recorded. Reuse the cards to compare actual methods, assumptions and limits, and return to the retained body when a new question needs more reading.

## Link manuscript claims to actual evidence

`research_workspace.py evidence --root ROOT --ledger LEDGER_JSON --output-dir NEW` records exact source witnesses for a manuscript. The ledger names a root-relative `manuscript` and a `claims` list. Each claim has `id`, `claim`, `kind`, a literal `manuscript_quote`, and `sources`. Each source has root-relative `path`, `start_line`, `end_line`, literal `quote`, and optionally an expected `sha256`.

Use `source_declared`, `observed_static`, `derived`, `proposed`, or `measured` to distinguish the claim's actual basis. The report records the exact manuscript snapshot hash used to locate its quotations. A verified quote/hash proves that the witness is locatable; the agent must still judge whether it supports the claim. A proposed policy is not an evaluated fix. A measured label needs real retained measurements. Preserve missing/mismatched witness results, rather than silently repairing a quote to pass. Keep lengthy details in the companion while pinpointing consequential evidence in the article.

## Compare revisions and inspect manuscript consistency

`research_workspace.py impact --root ROOT --evidence PRIOR_EVIDENCE_JSON --output-dir NEW` compares a retained generated `evidence.json` with current source bytes and manuscript quotations. Optional `--manuscript ROOT_RELATIVE_MD` selects a revised manuscript; optional `--focus FOCUS_JSON` supplies `{question, claim_ids: [...], source_paths: [...]}` for explicit new-question reading choices. It identifies changed/missing sources and all dependent claims, absent manuscript quotations, previously unverified bindings, and unchanged literal bindings eligible for reuse. A changed source conservatively affects every dependent claim even when its old quote remains.

Use this report to revisit affected claims and reuse unchanged retained witnesses without rereading unrelated bodies. Explicit new-question selections still require relevant reading, even when their hashes match. Selection is supplied judgment, not automatic semantic relevance. An unchanged binding does not establish claim truth, prove that a new question is answered, or reassign an earlier scientific review to revised manuscript bytes. The report creates no cache database, resets no counters and triggers no study. Exit0 means the impact snapshot was prepared, including when it identifies review work.

`research_workspace.py compare --before BEFORE_MD --after AFTER_MD --output-dir NEW` retains an exact textual diff and structural summary. It does not infer scientific improvement, recompute an old score, or claim an old review covers changed bytes. Use the diff to explain actual changes and unresolved issues to the author.

`scripts/editorial_checks.py check --manuscript MANUSCRIPT_MD --output-dir NEW` checks local citation/reference structure, repeated identifiers, table/figure callouts and selected editorial consistency. Optional `--references-json FILE` supplies a list of bibliographic metadata records such as `id`, `title`, `doi`, `authors`, `year`, and `url`. These are supplied facts, not verified metadata. Resolve uncertain DOI/title/author details against actual primary records using the agent's available research tools and retain those retrievals separately. This offline helper makes no publisher request and cannot detect every retraction or validate a paper's identity.

Keep definite structural findings separate from heuristic suggestions. Acronym-first-use, naming, caption matching and possible duplicate titles need contextual review; code, symbols and official names can be legitimate exceptions. Do not automatically edit the manuscript or block delivery on a heuristic. The existing official exporter remains responsible for native format and exact-file page checks.

## Reuse author and coauthor facts

Save an explicit profile outside the skill and provide it for each paper. `scripts/submission_support.py authors --profile PROFILE_JSON --manuscript MANUSCRIPT_MD --output-dir NEW` validates ordering and facts, prepares a new Markdown author block/biographies and a separate missing-information report, leaving the input unchanged. The profile contains `authors` entries with `id`, `author` and `contributions`, an `order` list, and an optional `corresponding_author` ID, `funding` and `conflicts`.

The nested `author` object uses the explicit exporter fields, including names, affiliation, department, city/country, email, ORCID, biography and factual `biography_details`. Use the public ORCID helper to collect available facts, then have the actual author select the submission affiliation/contact. Retain missing facts; no recorded end date does not prove a current appointment. Contributions are supplied descriptions, not a certified contribution taxonomy or agreement from coauthors. Author order, corresponding-author designation, funding/conflicts, rights and final approval need genuine confirmation for the particular paper.

Author slots use `<!-- paper-factory:authors:start -->` and `<!-- paper-factory:authors:end -->` around the dedicated byline. Ambiguous unmarked material before Abstract is refused before output; inspect it and mark only the known author block in a new copy. Never place unrelated prose inside an author slot. Repeated preparation replaces only that slot and the dedicated biography section, preserving other prose.

Use the new Markdown and generated `authors.json` together with the official exporter: `export_manuscript.py ... --profile AUTHORS_JSON`. Preparation and export share the same multi-author profile contract and report missing fields for every author, including factual biography details. The exporter does not rewrite the byline from the profile. Adding author material changes the delivered bytes; retain the scientific version/review binding and check the new output and venue word-count rules. Do not insert unconfirmed profile choices or treat a field's presence as consent. A saved profile is not included in a checkpoint or submission bundle unless explicitly selected.

## Prepare an anonymous draft only when appropriate

`authors ... --anonymous` additionally prepares a separate Markdown draft without its dedicated author block and biography sections. Use only when requested or when the verified article category requires anonymity. Read the residual-identifier findings and inspect self-identifying prose, acknowledgments, citations, source URLs, supplements and file names. This targeted text operation is not comprehensive anonymization and does not scrub metadata in an existing DOCX or PDF.

`submission_support.py metadata --file ACTUAL_DOCX_OR_PDF [--profile PROFILE_JSON] --output-dir NEW` reads native metadata and reports possible supplied-identity matches. DOCX checks also report comments/tracked-change residue; PDF inspection is limited to the exposed metadata fields. It does not remove or certify the absence of identifiers in content, attachments or images. After any anonymous export, inspect this report and the actual pages before representing the output as fit for anonymous review. A clean literal metadata result alone is not anonymity approval.

## Respond to actual reviewer comments

`submission_support.py responses --comments COMMENTS_JSON --before BEFORE_MD --after AFTER_MD --output-dir NEW` prepares a response letter and anchor report. Supply a `comments` list containing `id`, the actual `comment`, `status` (`pending`, `addressed`, `not_changed`), an honest `response`, and `changes` with exact revised-text `quote` values and optional section labels.

The tool checks whether the cited revised text exists; it does not establish that the revision satisfies a reviewer, that a claim is sound, or that work was executed. A `not_changed` response needs an explanation. Inspect the report's summary counts for pending comments, incomplete responses and missing anchors; `response_draft_complete` means preparation checks passed, never scientific resolution. With no change anchors, `all_change_anchors_present` is null rather than a vacuous success. Exit0 means the report was prepared and can include unfinished work. Draft a response from the actual change and evidence. Retain disagreements and unresolved requests explicitly. Do not manufacture reviewer comments, completed experiments or acknowledgments. Preparing a response letter is not another full-article assessment and does not authorize sending it.

## Assemble an explicit submission-file bundle

`submission_support.py bundle --root ROOT --plan PLAN_JSON --output-dir NEW` copies only the explicitly selected root-relative files, records hashes, and produces a checklist. A plan has `venue_id`, `title`, `files` entries with `role` and `path`, optional `cover_letter.text`, and supplied `declarations`. Identify the manuscript and any required photographs, figures or companion through the plan; inspect the generated pending/required checklist.

`declarations` stores text or null for `originality`, `rights`, `author_approval`, `funding`, `conflicts` and `ai_disclosure`. Supplied text such as “Author must confirm” never checks off approval. Optional `confirmations` stores actual author-provided records per declaration: `confirmed: true`, `confirmed_by`, timezone-aware `confirmed_at`, `declaration_sha256` of the exact UTF-8 statement, and `files: [{path, sha256}, ...]` matching the report's entire `approval_files` list. Those paths are final bundle-relative paths: `files/<selected path>` plus generated `cover-letter.md` when present. The generated letter's exact UTF-8 bytes and final newline are included; changing its text invalidates old confirmations. Select a cover-letter file or provide generated text, not both.

Prepare confirmation records only from genuine confirmation; never fabricate one to complete the checklist. Missing, changed or incomplete bindings remain pending. The helper records supplied confirmations without independently authenticating them, and never marks actual submission complete.

Write a cover-letter draft in the current conversation from the actual article, fit and supplied facts before including it. Never insert unsupported novelty, exclusive submission, consent, rights, funding or approval declarations to make a complete-looking package. The checklist is a preparation aid, not complete current publisher certification. Confirm the actual article category, current portal requirements and source rights at submission. No profile/credential directories are discovered or copied implicitly. Actual login, upload, author approval, submission and receipt require separate authorization and real outcomes.

## Reconcile final preparation records

`scripts/finalize_submission.py check --root ROOT --record RECORD_JSON --output-dir NEW` reads existing reports and actual chosen files to prepare one final status, without Word, new scientific review or submission. The record has exactly `venue_id`, `manuscript`, `docx`, `pdf`, `format_report`, `visual_review`, `bundle_report`, `scientific_review`, `pages` and `confirmations`. File fields use root-relative paths; the three review/bundle fields may be null when absent. `pages` lists the actual ordered PNG paths. Keep all selected reports and files below a common explicit root, using new copies if needed rather than changing old reports.

The helper rechecks actual native/template/file bindings, the supplied all-page visual record, the bundle's current `approval_files`, every author's recorded completeness, and a scientific assessment covering the exact manuscript/venue. It preserves original reports and reports format, page inspection, administrative preparation and scientific recommendation separately. A retained earlier review is not current merely because only author preparation changed the new file's complete hash.

`confirmations` may contain `author_identity`, `current_guidance`, `required_files`, and, for Software, `author_photo`. Each uses an actual supplied `statement` with the same confirmed/by/dated/declaration-hash/files contract as declarations, bound to the complete final bundle scope. A photo selection is needed for each named author; the actual person confirms the identities and rights. A recorded current-guidance confirmation is supplied evidence, not the helper browsing the publisher or independently authenticating a person. Missing facts or confirmations stay pending. Do not manufacture these records.

`submission_ready` can become true when all exact-file preparation records pass; it means preparation based on those supplied records, not acceptance or an actual submission. `actual_submission_performed` remains false. Exit0 means prepared, Exit1 means pending items were reported, and Exit2 means invalid inputs or a changed-file race. Inspect the separated states instead of treating an old exporter `pending` flag as permanently unresolved after genuine later confirmation.
