# Paper Factory

공개 GitHub 저장소를 바탕으로 연구를 설계하고, 문헌·연구 적합성·실험·원고를 검토해 **논문 초안과 재현 자료를 만드는 데스크톱 앱**입니다. 원고 검토에서 드러난 문제를 보완하고, 추가 측정이 필요한 경우에는 별도 후속 연구를 설계합니다. 저장소 주소와 연구 목표를 입력하면 진행 상태와 결과를 앱에서 확인할 수 있습니다.

현재 소스 버전은 **0.14.5**입니다. 최신 검증 범위와 설치 파일 정보는 아래 검증 상태에서 확인할 수 있습니다. 새 설치본의 설치·로그인 전체 흐름은 별도로 검증하지 않았습니다. macOS 빌드 설정도 포함되어 있지만, 네이티브 실행·설치는 검증하지 않았습니다.

연구 적합성 검토는 0.14.0부터, 원고 반려에 따른 연구 재설계는 0.14.2부터 제공됩니다.

- 공식 **Continue with ChatGPT**로 자신의 ChatGPT 계정을 연결합니다.
- Paper Factory 별도 회원가입이나 운영자 서버의 계정 등록 없이 사용합니다.
- 설치본에는 실행 환경이 포함되어 있어 Python·Node.js·Docker를 따로 설치할 필요가 없습니다.
- 현재 실험 대상은 지원 가능한 **JavaScript·TypeScript 함수**입니다.

## 설치

배포받은 `Paper Factory Setup 0.14.5.exe`를 실행하고 설치 위치를 선택한 뒤 **Paper Factory**를 엽니다. 인터넷 연결과 모델을 사용할 수 있는 ChatGPT 계정이 필요합니다.

**배포 상태:** 0.14.5 설치 파일을 생성하고 검증했으며 `desktop/release/`에 보관했습니다. 이 작업에서는 GitHub Releases에 설치 파일을 게시하지 않았습니다. 이 저장소의 소스 ZIP은 실행 가능한 설치 파일이 아닙니다.

## 처음 사용하기

1. **연결** 화면에서 **Continue with ChatGPT**를 누르고, 브라우저에서 로그인과 권한 동의를 완료합니다.
2. 사용할 계정을 선택하고 **모델 새로고침**을 누릅니다. 모델을 선택한 뒤 **실제 응답 확인**으로 짧은 요청이 정상 완료되는지 확인합니다. 이 요청도 모델 사용량을 소모합니다.
3. **새 연구**로 이동해 **실행 환경 준비됨**을 확인합니다.
4. 공개 GitHub 저장소 주소와 연구 목표를 입력합니다. 계정 주소를 입력했다면 **공개 저장소 조회**를 누르고 목록에서 저장소를 선택합니다.
5. **작성 모델 (writer)**과 **리뷰 모델 (reviewer)**을 선택하고 **연구 시작**을 누릅니다.
6. **결과**에서 단계·오류·완료 상태를 확인하고 필요한 파일의 **저장** 버튼을 누릅니다.

예를 들어 아래와 같이 입력할 수 있습니다. 실제 실험 가능 여부는 저장소 분석과 계획 검증에서 결정됩니다.

| 입력 | 예시 |
| --- | --- |
| 저장소 | `https://github.com/owner/repository` |
| GitHub 계정 | `https://github.com/owner` — 최근 업데이트된 공개 저장소 최대 100개 조회 |
| 연구 목표 | `실제 사용에서 발생하는 재전송·충돌 사례를 바탕으로 기존 병합 정책을 비교하고, 어떤 조건에서 데이터가 유실되는지 밝히고 싶어요.` |

연구 목표는 최소 8자이며, 밝히려는 문제·비교할 방법·실제 사용 상황을 구체적으로 적을수록 좋습니다. 동작 확인이나 일부러 기능을 생략한 구현과의 비교만으로는 연구 기여가 충분하지 않을 수 있습니다. 모델은 연결된 계정에서 조회한 목록 중 선택합니다.

로그아웃하려면 **연결 → 연결 해제**를 누릅니다. 선택한 계정의 Paper Factory 연결을 해제하며 연구 파일은 보존합니다. 다른 앱의 로그인 상태를 변경하는 기능은 아닙니다.

## 연구는 어떻게 진행되나요?

| 순서 | 하는 일 |
| --- | --- |
| 1. 원본 수집 | 선택한 저장소의 원본과 라이선스를 고정하고 연구에 사용할 코드를 확인합니다. |
| 2. 연구 설계·문헌 수집 | 연구 질문, 기여, 비교 방법, 표본과 분석 방법을 제안하고 관련 문헌을 수집합니다. 이때 계획은 아직 확정되지 않습니다. |
| 3. 연구 적합성 검토 | 별도 문맥의 리뷰 요청에서 질문·기여·문헌·비교 대상·표본 설계·실행 가능성을 기준별로 평가하고 사용할 문헌 근거를 선정합니다. 통과한 계획만 고정합니다. |
| 4. 실험 코드·리뷰 | 고정된 계획에 따라 실험 코드를 작성하고 별도 문맥에서 검토합니다. |
| 5. 실험·분석 | 제한된 QuickJS 환경에서 실험하고 관측·제어 검사·분석 결과를 보존합니다. |
| 6. 원고·품질 검토 | 보존된 근거와 선정 문헌으로 원고를 작성합니다. 별도 문맥에서 연구 기여·문헌 사용·결과 해석·내용과 분량을 평가하고, 실패 기준별 보완 행동과 부족한 증거를 기록합니다. |
| 6a. 보완·연구 재설계 | 기존 근거로 고칠 수 있으면 원고를 보완합니다. 새 측정이 필요하면 원래 자료와 결과를 보존한 별도 연구에서 질문·비교·표본을 바꾸고 설계·문헌·코드를 다시 심사합니다. |
| 7. 파일 생성 | 검토를 통과한 원고와 재현 자료를 내보냅니다. |

연구 설계는 최초 제안을 포함해 최대 3회 검토·보완합니다. 최종 검토에서도 기준을 충족하지 못하면 **연구 보류**와 판단 이유를 표시하고 실험·원고 생성을 진행하지 않습니다. 거부된 제안과 검토 기록도 보존합니다. 목표나 비교 방법을 바꾸려면 새 연구로 시작하세요.

검색 실패나 관련 없는 문헌만 확보된 경우에는 남은 설계 기회 안에서 구체적인 제목·방법 검색어·알려진 DOI로 검색을 보완합니다. 문헌 제공자의 일시적인 요청 제한에는 제한된 대기·재시도를 적용하며, 시간 초과나 취소로 수집이 끝나지 않았다면 완료 후에만 연구를 승인할 수 있습니다.

지원하는 실행 환경과 확보한 근거로 적합한 설계를 마련할 수 없으면 제안 단계에서도 **연구 보류**가 됩니다. 초기 제안은 검색할 문헌을 정하며, 아직 문헌을 수집하지 않았다는 이유만으로 보류하지 않습니다. 수집 후 관련 근거와 연구 기여가 부족하면 연구 적합성 검토에서 보류합니다. 문헌의 제목·DOI·서지 정보만으로 본문을 읽었다고 판단하지 않으며, 확보한 초록이나 본문 발췌의 범위 안에서 근거를 검토합니다.

검증이나 리뷰가 실패하면 해당 상태와 오류를 표시합니다. 재시작이나 응답 중단을 이유로 과학실험을 자동으로 다시 실행하지 않습니다. **원고 생성 완료**는 파일 생성까지 끝났다는 뜻입니다. 모델 검토는 학술지 심사나 채택을 의미하지 않으며, 제출 전 원문 문헌·실험 설계·연구 기여를 사람이 확인해야 합니다.

최초 원고를 포함해 한 작성 구간에서 최대 3차례 작성·검토하며, 자동 연구 재설계는 최초 연구 뒤 최대 2회입니다. 재설계는 표현이나 난수 시드만 바꾼 반복 실험을 허용하는 절차가 아닙니다. 새 계획은 반려에서 확인한 과학적 증거 부족을 해결해야 합니다. 이전 결과는 탐색적 근거로 표시하고 후속 연구의 새 관측과 구분합니다. 각 연구의 과학실험은 한 번만 실행하며, 이전 계획·관측·원고·검토 기록은 보존합니다. 후속 연구의 재현 ZIP에는 이전 연구의 보존 근거도 포함합니다.

리뷰가 현재 목표와 실행 환경에서 확보할 수 없는 증거를 구체적으로 요구하거나 보완 한도에 도달하면 필요한 근거와 보류 이유를 표시합니다. 기준을 낮추거나 부족한 측정값을 만들어 통과시키지 않습니다.

## 결과 저장

**결과** 화면에서 형식별 **저장** 또는 **열기**, **결과 폴더 열기**를 사용할 수 있습니다. 파일 열기는 운영체제의 기본 문서 앱을 사용합니다.

| 형식 | 내용과 저장 방식 |
| --- | --- |
| PDF | 읽거나 공유할 원고. 기본 파일 저장창에서 위치 선택 |
| Word (`.docx`) | 편집 가능한 원고. 기본 파일 저장창에서 위치 선택 |
| Markdown (`.md`) | 원고와 참조 파일을 선택한 위치의 새 하위 폴더에 함께 저장 |
| LaTeX (`.tex`) | 원고와 참조 파일을 선택한 위치의 새 하위 폴더에 함께 저장 |
| 재현 패키지 ZIP | 실험 코드·원시 관측·분석·검증 기록. 기본 파일 저장창에서 위치 선택 |

저장 전에 내보낼 파일의 무결성을 확인합니다. 쓰기가 끝난 임시 파일이나 폴더를 최종 위치로 옮기므로, 선택 취소나 쓰기 실패로 기존 내보내기를 덮어쓰지 않습니다.

원고는 근거에 맞는 분량으로 작성합니다. PDF의 통계 표는 긴 지표·단위·조건 이름을 줄바꿈하며, 전체 정밀도의 값과 요약은 분석 JSON·CSV에 보존합니다.

## 중단하거나 이어서 작업하기

- **연구 취소:** 실험 종료와 기록 보존을 확인한 뒤 작업 잠금을 해제합니다. 확인이 끝날 때까지 새 연구와 계정 변경을 기다려 주세요.
- **정리 다시 확인:** 정리가 확인되지 않은 연구에 표시됩니다. 로그인 없이 사용할 수 있으며, 종료와 기록 보존을 다시 확인합니다.
- **연구 준비 재개 / 원고 작성 재개:** 보존된 상태에서 이어갈 수 있을 때만 표시됩니다. 작성·리뷰 모델을 선택하고 버튼을 눌러야 재개됩니다. 최종 연구 적합성 반려, 실행 여부가 불명확한 실험, 제어 검사가 실패한 실험은 재개하지 않습니다.
- **원고 수정:** 현재 기준의 연구 적합성·원고 검토를 통과한 완료 연구의 실험 결과를 유지한 채 새 원고와 리뷰를 작성합니다. 검토 기록이 없는 과거 결과는 그대로 열고 저장할 수 있습니다.
- **심사·보완 이어가기:** 성공한 실험과 안전한 정리가 확인된 보류 원고에 표시됩니다. 기존 결과로 새 원고·검토를 작성하거나, 이미 확인된 증거 부족에 따라 별도 후속 연구를 만듭니다. 이전 검토에 보완 판단이 없다면 기존 검토 이유로 새 원고를 작성하고, 새 검토에서 보완 방향을 판단합니다. 이미 후속 연구가 있다면 **후속 연구 보기**로 상태를 확인하고, 재개가 가능하면 표시되는 버튼을 사용합니다.
- **추가 근거 선택:** 준비·연구 제안·계획·분석 후 대기 중인 연구에 원문 문서를 추가합니다. 가져오기만으로 연구를 재개하거나 실험 결과를 바꾸지 않습니다.

추가 근거는 영문 파일명의 UTF-8 `.md`·`.txt`·`.json`을 지원합니다. 파일당 128 KiB, 연구당 최대 8개·총 256 KiB까지 보존합니다.

실험 코드는 고정 계획에 선언된 소스와 가져온 문서의 원문을 읽어 출처·입력 생성을 확인할 수 있습니다. 앱이 원본 바이트와 해시를 대조하며, 이 읽기 기능은 생산 함수에 노출되지 않습니다. 임의 파일이나 네트워크에 접근할 수 없습니다.

앱을 닫으면 저장과 실험 정리를 기다립니다. 종료 확인에 실패하면 창을 유지하고 **정리 다시 시도**를 제공합니다.

## 계정과 데이터

인증 정보는 운영체제 보호 저장소로 암호화해 이 컴퓨터에 저장합니다. 화면과 연구 엔진에는 인증 토큰을 전달하지 않습니다. 모델 요청에는 연구 목표, 선정한 코드, 문헌과 추가 근거 등 필요한 자료가 OpenAI로 전송됩니다.

연구 기록도 이 컴퓨터에 저장합니다. Windows의 기본 앱 데이터 위치는 다음과 같습니다.

```text
%APPDATA%\Paper Factory Standalone\
├─ chatgpt\   계정 연결 자료
├─ evidence\  연결 확인·완료 응답·오류 기록
├─ research\  작업 목록과 모델 요청 기록
└─ engine\    원본·계획·실험·분석·원고·결과 파일
```

인증 자료가 들어 있는 `chatgpt/` 폴더를 공유하지 마세요. 이전 플러그인이나 구 버전 프로젝트의 연구 자료를 자동으로 가져오는 기능은 없습니다.

## 문제가 생겼을 때

| 증상 | 확인할 내용 |
| --- | --- |
| 연구 시작 버튼이 비활성화됨 | 계정 연결·모델 사용 권한, 실행 환경, 작성·리뷰 모델, 저장소 선택, 8자 이상 목표와 다른 작업의 완료 여부 확인 |
| 모델 목록이 비어 있음 | 연결 화면의 **모델 새로고침**과 계정 권한 확인 |
| 모델 사용량 한도 오류 | **사용량 확인**으로 ChatGPT 사용량과 크레딧 설정 확인 |
| 실행 환경 사용 불가 | **실행 환경 다시 확인**. 계속 실패하면 설치 파일로 재설치 |
| 취소 후 계정 변경·새 연구가 잠김 | 결과의 **정리 다시 확인**으로 실험 종료와 기록 보존 확인 |
| 연구 보류 | 표시된 기준별 이유를 확인하고, 연구 질문·비교 방법·근거를 보완한 새 연구 시작 |
| 원고 보류 | 실패 기준별 보완 행동·부족한 증거 확인. 표시되면 **심사·보완 이어가기** 또는 **후속 연구 보기** 사용 |
| 파일 저장 실패 | 다른 저장 위치 선택, 폴더 권한과 남은 공간 확인 |

ChatGPT 크레딧을 사용하려면 앱의 **크레딧 사용 설정**으로 공식 사용량 페이지를 열고, **사용량 한도에 도달한 후 다른 앱에서 크레딧 사용 허용**을 확인하세요. 앱의 확인 체크박스는 계정 설정 자체를 변경하지 않습니다.

## 개발

아래 명령은 소스 개발자용입니다. Node.js 24와 npm이 필요합니다.

```powershell
cd desktop
npm ci --no-audit --no-fund
npm run build:runtime
npm start
```

`build:runtime`은 해시로 고정한 실행 환경을 개발 단계에서 다운로드·검증합니다. 설치된 앱은 이 명령을 실행하거나 런타임을 따로 내려받지 않습니다.

```powershell
# desktop/에서 실행
npm test                 # 타입·빌드·controller·SDK 회귀
npm run test:electron    # Electron UI와 네이티브 IPC 검사
npm run package:app      # 런타임·설치 파일 생성과 패키지 검증
```

Windows 설치 파일과 패키지 검증 기록은 `desktop/release/`에 생성됩니다. 네이티브 IPC 검사는 해당 플랫폼의 런타임을 먼저 빌드해야 실행됩니다.

Python 엔진을 수정하거나 검사하려면 Python 3.11 이상이 필요합니다. 아래는 저장소 루트에서 실행하는 Windows 예시입니다.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,pdf]"
$env:PF_NODE_BIN = (Resolve-Path desktop/runtime/win32-x64/node/node.exe).Path
.\.venv\Scripts\python.exe -m pytest -q
```
