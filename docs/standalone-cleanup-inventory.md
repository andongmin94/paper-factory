# 현재 두 IEEE 매체 흐름의 코드 정리

2026-10-11 현재 요청 범위의 정리 결과다. 기존 연구·출력·횟수는 사용자의 전체 삭제 요청으로 초기화했고 새 Frontron 연구를 실제 앱에서 생성했다. 과거 9곳·JIZURA 작업을 현재 사용법이나 재개 지시로 보존하지 않는다.

| 영역 | 제거·단순화 | 유지한 책임 |
| --- | --- | --- |
| 대상 | 9개 학술지 catalog와 고정 9 분모를 두 IEEE Feature Article 대상으로 변경 | 적합성 판단·부적합 사유·동결 catalog |
| 새 연구 제어 | 범용 첫 원고·첫 심사 후 다시 매체별 작성하던 중복 경로와 전용 보정 helper 제거 | 설계→필요 근거→공통 분석→매체별 실제 원고 |
| 평가 순서 | 출력하지 않은 원고를 심사하는 순서 제거 | 현재 Word·PDF 성공과 형식 선검사 후 정확한 원고의 독립 평가 |
| 보완 | 문서 부족을 불필요한 공통 재분석으로 넘기던 순서 정리 | 실제 원고·심사 SHA에 연결된 공식 문서 확보→필요한 원고 수정→새 독립 평가 |
| 작업 종료 | 과거 수정 계획만으로 통과 원고를 다시 보완하는 경로 제거 | 현재 실제 심사 기준으로 다음 작업 계산, 모두 통과하면 중단 |
| 평가 계약 | 선택적 조언을 차단 issues로 기록하는 모호함 제거 | 차단 문제는 issues, 통과한 기준의 선택적 조언은 reason |
| 검사 | 폐기된 범용 첫 원고 fixture를 간결한 현재 라우팅 검사로 교체 | 요청 결속·실패 재호출 금지·원자료와 횟수·실제 출력 검사 |
| 문서 | 장문의 오래된 active 체크포인트와 폐기된 사용법 제거 | 현재 README·설계·인계·실제 검증 결과 |

새 의존성·호환 계층·마이그레이션·Frontron 특별 경로를 추가하지 않았다. 기존 공식 SDK, 자료 읽기·원문 수집·보존, 문서 변환과 Playwright를 사용한다. `LICENSE`, SDK upstream 원본과 provenance, runtime 해시·의존성·폰트 라이선스는 유지한다.

[현재 설계](ieee-magazine-redesign.md) · [인계](next-session.md) · [실제 검증](standalone-verification.md)

집중 검사 native21·shared/portfolio/recovery148·research/routing167·문서 selector6, 타입·앱 빌드·Windows runtime host 검사가 통과했다. 실제 숨김 Electron·정상 UI·공식 SDK로 두 수정 원고·Word/PDF·새 심사를 생성했고 두 매체의 내용 기준이 모두 통과했다. 보완 전 282개 파일의 bytes와 원 심사·실패·횟수는 유지됐다.

최종 Word 시각 검수·실제 저자 정보/승인·제출 확인은 남아 있다. 새 NSIS 설치본 배포나 실제 투고를 수행하지 않았다.

2026-10-12 푸시 준비에서 폐기된 9곳 계획·이전 Software 전용 설계 문서와 이미 실행한 특정 PC용 일회용 초기화 스크립트를 제거하고, 현재 문서의 로컬 증빙 경로와 검증 당시 SHA를 명확히 했다. 현재 Frontron 자료·심사·횟수는 유지한다. 브라우저 캡처·임시 검사 폴더·일회용 launcher·`tmp/`는 Git에서 제외했다. 해당 로컬 임시 파일의 삭제 명령은 자동 검토에서 거절돼 남았으며 앱 코드·runtime·연구 자료로 사용하지 않는다.
