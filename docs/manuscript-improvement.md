# 원고 품질 보완 흐름

이 흐름은 기존 연구의 원자료·분석·원고·심사·실패·횟수를 보존하면서 실제 원고의 기여와 근거를 보완한다. 새 연구를 만들어 횟수를 초기화하지 않는다. IEEE Software와 IEEE Security & Privacy의 대안 투고본을 대상으로 하며 동시에 두 매체에 제출하는 기능이 아니다.

기여·방법·재현성이 부족한 연구에는 [연구 설계와 근거 보완](research-development.md)을 사용한다. 새 질문·대안과 판단 조건을 설계하고, 생성형 유한 규칙 분석·약화 대조·조건 변화 계산·독립 방법 검토를 마친 뒤 두 원고를 한 번 작성·평가한다. 사용자가 별도로 선택하는 추가 최대 6회이며 기존 8회와 과거 추가 4회 사용량을 유지한다. 전체 영구 예약은 최대 18회다. 방법 보완은 한 번만 허용하고 마지막 점수에 따른 자동 재집필·재채점은 하지 않는다. 아래 기본/추가 4회 절차는 기존 이력과 해당 기능의 한도를 설명한다.

## 평가와 보완

기존 원고별 독립 평가 → 연구 방향 비교와 작업 선정 → 필요한 완전한 소스·공식 문서 확인 → 실제 원고 보완 → 새 원고 독립 평가 → 최선 원고 선정 → 공식 템플릿 Word·PDF와 평가 보고서 순서다. 새 저장소의 기본 작성 흐름도 매체별 초안 생성 후 이 품질 보완으로 이어진다. 기존 연구는 앱의 **항목별 품질 보완 이어가기**에서 같은 연구 ID로 진행한다.

외부 GPT의 원래 상세 평가표는 제공되지 않았다. 앱은 이를 동일한 평가표라고 주장하지 않고 `declared-magazine-quality-proxy-v1`을 명시한다. 추가 기여, 주장과 근거, 분석 방법, 선행·대안 비교, 실무 적용 가치, 논리, 표현·구성, 매체 적합성, 한계의 정확성의 9개 항목에서 각각 9/10 이상을 목표로 한다. 점수와 불확실성, 실제 인용 구절, 남은 문제가 함께 기록된다. 평균 점수로 약한 항목을 숨기지 않는다.

모든 항목 9점이나 외부 GPT의 같은 점수, 게재를 보장하지 않는다. 확보한 프로젝트·문헌으로 입증할 수 없는 효과는 한계로 남긴다. 남은 한도에서 가능한 비교·사례·반례를 완성하되 점수를 높이기 위해 같은 집필·평가를 반복하지 않는다.

독립 평가에는 현재 원고와 완전한 근거, 매체 규정, 고정 평가표를 전달하며 작성자의 자기 평가나 이전 점수는 전달하지 않는다. 단순히 정확한 설명이나 한계 고지를 했다는 이유만으로 충분한 기여라고 판정하지 않는다. 프로젝트 실행은 필수 조건이 아니며 정적 분석에서 실험 효과·배포·사람의 검증을 만들어 내지 않는다.

계획은 여러 완성 논문을 먼저 생성해 비교하지 않는다. 독자 문제·기존 접근·추가 판단 가치·확보한 자료·부족한 근거를 기준으로 연구 방향을 비교한다. 선정 작업에는 목표 항목, 필요한 실제 변경, 근거 증가, 예상 이득·비용·성공 가능성, 완료 조건이 있다. 모델이 제안한 문서는 실제로 보존된 본문과 인용을 확인해야 원고의 근거로 사용할 수 있다.

## 종료와 보존

- 기본 보완은 두 매체를 합쳐 모델 요청 최대 8회, 작업 최대 4개다. 종료 후 사용자가 **근거·투고규정 보완 4회**를 선택하면 같은 연구에 단 한 번 4회만 추가한다. 기존 예약과 정책을 별도 보존하고 한도는 기존 예약 수+4로 고정한다. 다시 클릭하거나 재개해도 추가 예산을 부여하지 않는다. 예약·실패·중단·검증 거절도 사용량에 포함한다.
- 한도는 네이티브 엔진이 예약 전에 검사한다. 기본 8회가 사용된 연구에서는 전체 예약 상한이 12회, 작업 상한이 4개에서 8개가 된다. SDK에 실제 전송한 요청과 네이티브 예약은 별도 증거로 계산한다. 전송하지 않은 예약이나 거절된 완료 응답이 있어도 이미 사용한 예약을 돌려주지 않는다.
- 원고 수정과 그 수정본의 독립 평가를 함께 완료할 예산이 없으면 새 집필을 시작하지 않는다.
- 동일 보완 경로에서 두 번 연속 실질적 진전이 없으면 그 경로를 중단한다. 다른 항목의 가능한 보완은 남은 전체 예산에서 판단한다.
- 확보 가능한 근거의 한계, 접근 실패, 예산 종료를 구분한다. 자료를 찾지 못했다는 이유만으로 프로젝트의 영구적인 한계라고 단정하지 않는다.
- 새 원고가 더 나쁘면 기존 최선 원고를 유지한다. 정확성·근거·방법과 가장 약한 항목을 문장 다듬기보다 우선한다. 필수 오류가 남으면 검토 초안으로 표시한다.

원고·심사와 SDK 요청 원문은 새 동결 산출물로 추가한다. 기존 횟수는 바뀌지 않으며 추가 품질 작업의 작성·평가·모델 요청 수를 별도로 누적해 표시한다. 보존된 이전 내부 PASS는 당시 기록으로 남기고 현재 품질 권고와 구분한다. 완료된 같은 응답을 다시 호출해 높은 점수가 나올 때까지 재평가하지 않는다.

모델이 작성한 참고문헌 절은 검증된 근거로 생성하는 참고문헌과 중복되지 않게 제거한다. 이미 거절된 완료 응답의 해당 형식 오류는 원 응답과 거절을 보존한 채 한 번만 복구하며 집필을 다시 호출하지 않는다. 같은 저장소·커밋의 여러 소스 증거는 한 참고문헌으로 묶되 개별 경로·인용·해시는 유지한다.

필수 오류가 없는 원고를 우선하고, 오류가 남은 후보끼리는 근거·방법·가장 약한 항목과 기여를 비교한다. 심사자가 문제를 몇 개의 문장으로 나눴는지는 심각도나 품질 척도로 사용하지 않는다. 최선 원고·저자·변환기 결속이 바뀌면 기존 출력을 보존하고 번호가 붙은 새 공식 출력과 보고서를 만든다. 같은 결속의 재확인은 모델 호출과 재변환 없이 기존 산출물을 사용한다.

## 출력과 투고

[공식 템플릿](official-templates.md)의 출처·원본 SHA와 입력·출력 SHA를 기록한다. 템플릿 준수, 실제 전체 페이지 검수, 내용의 게재 가치, 저자 승인, 접수 기록은 별개다. 전용 글꼴이 설치되지 않은 경우 Word의 대체 글꼴 사용을 기록하며 출판사의 최종 조판을 재현했다고 주장하지 않는다.

최종 권고는 **투고 검토 권장 / 투고 전 보완 필요 / 현재 투고 비권장**이다. 모든 항목 9점 달성과 투고 권고는 별도 판단이다. 선택한 최선 원고·독립 평가·저자 정보·공식 출력에 제출 준비를 결속하며, 이전 제출 준비는 원문을 보존한 채 최신 여부를 다시 계산한다. 이후 [기존 투고 흐름](submission-workflow.md)의 실제 저자 확인, 새 파일 검수, 제출 묶음과 공식 포털을 사용한다. 자동 승인이나 실제 외부 제출은 하지 않는다.

## 추가 4회에서 완성하는 연구 결과

**근거·투고규정 보완 4회** 한 번으로 예산 부여와 정상 재개를 함께 시작한다. 네이티브 엔진은 다음 네 목적을 순서대로 한 번씩 예약한다. 여러 완성 원고를 먼저 생성해 비교하는 절차가 아니다.

1. `focused-select`: 공급된 가까운 선행 방법 후보 중 2~3편과 고정 소스를 선택한다. 앱이 공개 PDF의 전체 페이지를 직접 수집하고 원본·텍스트·해시·저자/제목 일치를 보존한다. 최소 두 원문이 실제로 확보되어야 다음 분석으로 진행한다. 수집 실패를 프로젝트의 본질적 한계로 처리하지 않는다.
2. `focused-analyze`: 붙여넣기와 자동 저장의 완성된 검토표를 작성한다. 현재 구현을 추상화한 모형과 미구현 제안 모형에 동일한 초기 조건·불변식을 적용한다. 네이티브 검사기가 유한한 도달 상태와 반례 경로를 직접 계산한다. 완성된 분석과 검사 결과는 별도 동결 JSON 산출물로 보존하고 앱에서 열기·저장할 수 있다. 이는 프론트론 실행이나 실증 실험이 아니며 기존 실행 횟수를 늘리지 않는다.
3. `focused-write`: 하나의 응답으로 두 매체 원고를 작성한다. 완성된 사례·선행 방법 비교·검사 결과와 실제로 확보한 최소 두 선행 원문을 각 원고에 사용한다. 서지 정보와 직렬화 형식을 정리한 뒤 공식 템플릿 Word·PDF를 만들고 [실제 규정 검사](journal-compliance.md)를 수행한다. 원 응답과 실패한 후보도 보존한다.
4. `focused-review`: 형식 검사를 통과한 정확한 원고를 하나의 별도 요청에서 평가한다. 이전 점수·자기 평가 없이 근거와 현재 원고를 전달한다. 원고별 검증 결과를 따로 수락하므로 한 매체의 실패가 다른 매체의 유효한 평가를 지우지 않는다.

형식 오류가 남으면 해당 원고를 투고 준비 완료로 표시하지 않는다. 실패한 같은 단계를 자동으로 다시 호출하지 않으며, 이번 네 단계의 종료 이유와 미진행 단계를 남긴다. 이미 보존된 더 나은 원고를 유지할 수 있다.

완료된 분석 응답이 보존된 논문 인용을 코드 증거 목록에 잘못 넣은 경우에는 좁은 결정적 분류 복구를 제공한다. 문헌 ID·텍스트 산출물 ID·SHA·정확한 인용이 모두 맞고 어떤 상태 전이에서도 코드 증거로 참조하지 않는 항목만 별도 증명으로 분리한다. 코드 인용, 주장, 검토표, 상태·전이·불변식은 바꾸지 않는다. 전체 원문·모형 검사를 다시 통과해야 같은 추가 한도의 남은 단계로 재개할 수 있다. 원 응답·거절·종료 보고서는 그대로 남기며 모델 재호출이나 예산 재부여는 없다.

완료된 집필 응답이 같은 원문 증거를 `literature_evidence`와 `{{citation:…}}`에 넣었지만 실제 자료가 보존된 전문 문서인 경우도 제한적으로 복구한다. 실제 문헌 ID·전문 텍스트 SHA·정확한 인용문·기존 인용 토큰이 모두 일치하는 항목만 `document_evidence`와 해당 문서 토큰으로 옮긴다. 원고의 과학적 주장과 인용문을 새로 쓰지 않는다. 모호한 중복, 잘못된 ID·해시·인용, 그 외 집필 오류는 이 경로로 통과시키지 않는다. 정규화 전후 해시와 변경 증명을 보존하고 원래 소스 검증 및 실제 공식 양식 검사를 다시 수행한다.

두 복구 모두 같은 거절 응답마다 한 번만 수행한다. 성공한 분석 복구는 뒤의 집필·독립 평가를 위한 최소 2회, 집필 복구는 독립 평가를 위한 최소 1회의 기존 잔여 예산이 있어야 재개한다. `analysis_repairs`와 `writer_repairs`에 별도 수락·거절 증명을 추가하며 원래 `calls`의 거절 상태·오류·SDK 원문은 바꾸지 않는다. 앱은 완료 단계와 함께 **분류 복구의 추가 모델 요청 0회**를 표시한다. **최선 원고·공식 출력 다시 확인** 등 일반 재개는 이 검증과 남은 단계만 이어가며 추가 4회를 다시 부여하지 않는다.

집필·평가 입력에는 현재 완성된 분석, 실제 전체 소스·선행 원문과 필요한 문서를 제공한다. 이미 대체된 과거 분석·계획·심사 이력은 중복 전송하지 않고 보존 위치와 해시로 표시한다. 독립 평가에는 이전 점수를 주지 않는다. 입력 한도 검사는 예약과 작업 수를 늘리기 전에 수행한다.

최종 제출 단계에서는 실제 저자 약력의 직위·소재지·관심 분야·최종 취득 학위·학위 기관·학회 회원 여부를 직접 입력한다. 해당 사항이 없으면 사실에 맞는 None/N/A 등을 명시하며 미정인 사실을 자동 생성하지 않는다. 공개 ORCID 정보는 이름·소속 등의 입력 보조이며 실제 약력·동의·권리를 대신하지 않는다. 서로 다른 영문 키워드 3~8개는 앱의 준비 정책이다. IEEE Software의 실제 저자 사진, 연구비·이해충돌 정보도 사용자가 제공한다.

앱은 제공한 약력·키워드·연구비·이해충돌을 새 제출용 Word·PDF에 반영하고 실제 분량과 모든 PDF 페이지를 다시 검사한다. 원고·독립 평가·저자·새 파일 SHA와 규정 검사에 결속된 준비본을 만든다. 자동 검사 실패와 실제 저자 정보·동의 대기는 별도로 표시한다. 과거 준비본과 승인 기록을 새 파일의 승인으로 가져오지 않는다. 새 파일의 Word·PDF 페이지 수, 단어 수, 표·그림 수는 실제 측정과 맞아야 하며 모든 저자의 승인·독창성·권리·AI 공시·투고 안내·전체 페이지 직접 확인은 사용자가 별도로 확인해야 한다. 이 확인을 마친 뒤에만 제출 묶음을 생성한다. 실제 외부 투고는 공식 포털에서 사용자가 진행하고 접수 번호로 기록한다.
