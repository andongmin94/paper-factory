## Reviewed policy specifications

`PolicySpec` is a strict JSON document. The compiler consumes typed `PolicyValues`; each fact requires a `PolicyEvidence` entry with an exact visible source excerpt and the researcher's interpretation. `reviewed_by` names the person who checked those interpretations. Retrieval time is generated by the application, never accepted from the specification. Merely downloading a guidelines page does not establish a fact or mark a policy verified. Unknown fields remain explicit `review_needed` issues; a useful draft package can still be produced with blockers.

The supplied facts cover scope, article types, current indexing, publisher, OA/APC, preprints, AI permissions/disclosure, data/code, word and character limits, keywords, peer-review/anonymization, declarations, submission URL/system, initial format/template requirements, accepted file and figure formats, citation style, page/line numbering, sections and supplements. `null` limits mean explicitly unlimited only when backed by reviewed evidence; omission means unknown. `citation_style: null` means that the reviewed initial submission rule does not prescribe a style. A charged APC requires an amount and uppercase three-letter currency; a general fee-assistance program is not an individual granted waiver.

Declaration values use names matching the author's declaration map, for example `funding`, `conflict_of_interest`, `data_availability`, `code_availability`, `author_contributions` and `ai_disclosure`. Any additional publisher requirement can be named explicitly in the same map. Unsupported exact templates and missing declarations must remain package blockers, not silently be replaced by generic layouts or claims.

This partial specification records one reviewed PLOS limit and deliberately leaves all other requirements unverified. Replace `venue-id` with a discovered record ID. Complete the other fields using their own official excerpts before expecting readiness.

```json
{
  "venue_id": "venue-id",
  "sources": [
    "https://www.plosone.org/",
    "https://journals.plos.org/plosone/s/submission-guidelines"
  ],
  "official_origins": [
    {
      "origin": "https://journals.plos.org",
      "rationale": "The discovered official homepage redirects to the publisher's current journal website.",
      "evidence_url": "https://www.plosone.org/",
      "evidence_excerpt": "PLOS One Skip to main content"
    }
  ],
  "values": {"manuscript_word_limit": null},
  "evidence": {
    "manuscript_word_limit": {
      "source_url": "https://journals.plos.org/plosone/s/submission-guidelines",
      "excerpt": "There are no restrictions on word count, number of figures, or amount of supporting information.",
      "interpretation": "The manuscript has no word-count maximum; other file and formatting requirements still need review."
    }
  },
  "reviewed_by": "Replace with the actual reviewing researcher",
  "ttl_days": 7
}
```

The example's homepage redirect and guideline retrieval were actually exercised on 2026-09-30 against a freshly discovered PLOS One record. Both returned readable official pages over verified HTTPS with public-address pinning; the partial result remained `review_needed`. This smoke establishes retrieval and blocker behavior, not PLOS eligibility, present SCIE coverage or a submission-ready manuscript.

## Provenance, freshness and network boundaries

The allowed publisher origin starts with the homepage in the captured directory record. An additional origin requires an explicit researcher rationale, a reviewed excerpt on that original origin, and an actual official hyperlink or redirect proving the connection. A guessed sibling domain is not trusted. MJL is separately allowed solely for indexing evidence; a journal-specific indexing excerpt must name one of the discovered journal's ISSNs and its exact SCIE/ESCI collection.

Requests reject credentials, HTTP policy sources, unusual ports, local hostnames, private/reserved addresses, and redirects outside the verified or explicitly nominated publisher origins. DNS results are checked before every connection and the request connects to the checked public IP while retaining the original Host header and TLS certificate hostname. This prevents a second DNS lookup from turning a validated hostname into a private target. Proxy environment settings are disabled for the application's own clients. Requests use a 20-second HTTP timeout, at most five redirects, at most 20 explicit source URLs, and a 4 MiB decompressed response cap; the parser executes no remote code.

Each verification or refresh saves a new policy ID, original specification, raw responses, normalized text, retrieval dates, content hashes and a receipt matching the stored record. It never overwrites the previous policy evidence. Local validation rechecks all these hashes and that readable text is derived from the raw capture, then rechecks excerpts, typed facts and freshness. The default maximum policy age is seven days; the researcher may explicitly choose one to thirty days. Compiler/package preparation must still refresh policy pages live on every run rather than treating TTL as a replacement for live verification. Changed text, unknown rules, authentication-only pages and network failures produce actionable blockers; no guessed rule or hidden fallback establishes readiness.

Publisher interpretation is a researcher review, not automatic scientific or legal certification. The snapshot tells the reviewer which exact source supported each supplied fact. Submission upload, account login, author attestations, fees, CAPTCHA/MFA, and final journal submission remain separate actions outside this Phase 2 package builder.

## Reproducible product smoke

With Pandoc installed and the `pdf` extra enabled:

```powershell
.\.venv\Scripts\python.exe scripts\phase2_smoke.py --pandoc C:\path\to\pandoc.exe
.\.venv\Scripts\python.exe scripts\phase2_smoke.py --pandoc C:\path\to\pandoc.exe --live
```

The default run makes no network requests. It executes the actual bundled corpus-compression script, verifies real numeric evidence, records a conspicuously synthetic reviewer approval, freezes the manuscript, and mocks the directory and full reviewed policy. Pandoc and Typst actually generate PDF, LaTeX and DOCX. The local package reaches `SUBMISSION_READY` for that synthetic fixture, deliberately altered table content is rejected, and restoring the table leaves a valid archive. A mocked empty literature search establishes no novelty and introduces no invented citation. Real author environment fields are excluded from the synthetic test. The summary records whether source verification occurred initially and again at both compile/package stages.

`--live` additionally queries OpenAlex for PLOS One and retrieves its official homepage and instructions. It builds an actual draft PDF and a blocked package whose unresolved policy requirements remain listed. It supplies only the reviewed word-limit excerpt above; it never invents SCIE coverage or other unknown rules. Both paths write their workspace, output and `phase2-smoke-result.json` to a new external temporary directory by default; `--root` can choose an explicitly empty output directory. These demonstrations neither upload a manuscript nor create an external journal submission.
