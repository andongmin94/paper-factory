## 이번에 개선한 흐름

새 연구는 기존 문헌 계획 요청에서 소스에 근거한 질문 후보 2~3개·가까운 접근·반박 조건·근거 요구와 검색 계획을 만든다. 실제 원문 확보 뒤 공통 분석에서 모든 후보를 비교하고 답할 수 있는 질문을 선택한다. 잠정 질문을 버리고 다른 질문을 선택할 수 있으며 모델 단계를 추가하지 않는다.

새로 명시적으로 시작하는 연구 보완 회차는 contract 3이다.

1. 질문 후보와 근거 확보 계획을 만든다.
2. 앱이 기존 문헌 수집기로 실제 가까운 원문과 필요한 소스를 확보한다.
3. 실제 근거로 질문을 선정하고 대안 비교·발견·분석 산출물을 완성한다.
4. 구체적인 빈틈이 있으면 한 번만 추가 수집·내용 강화를 한다.
5. 최종 근거에 대한 독립 방법 검토를 수행한다.
6. 집필 가능한 경우 두 매체 원고를 한 요청으로 작성하고 공식 Word/PDF 템플릿을 적용한다.
7. 정확한 새 원고를 독립 평가한다.

모델 요청은 기본 **5회**, 내용 강화 포함 **최대 6회**다. 최초 검색어 최대 4개·후속 최대 2개, 각 수집 결과 최대 6개, 두 수집을 합친 PDF 접근 예약은 2회다. 질문을 선택할 근거가 없거나 집필 준비가 안 되면 완료한 연구 보고서와 한계를 남기고 끝낸다. 감사 후 자동 보완·재집필·재채점 루프는 없다.

일반 저장소는 `source_comparison`이 기본이며 무관한 유한 모형을 강요하지 않는다. 집필에는 선택 질문·가까운 방법의 정확한 인용·완료한 발견과 비교 산출물을 `writer_brief`로 전달한다. 새 문헌은 실제 원고의 인용·참고문헌과 공식 출력에도 연결한다. 내부 검사 통과나 감사의 집필 허가는 학술적 기여·투고 권고의 증거가 아니다.

## 재개 시 확인

1. Git 상태와 최신 문서를 먼저 읽고 위 연구·원고·횟수를 그대로 보존한다. 종료된 보완 회차를 자동 재개하거나 예산을 다시 부여하지 않는다.
2. Windows에서 Docker 없이 작업한다. 실제 앱 검증이 필요하면 숨김 packaged Electron과 Playwright를 사용한다. 합성 검사·빌드 검증·실제 연구 실행은 증거에서 구분한다.
3. 다른 PC에는 연구·패키지·인증이 Git clone만으로 복원되지 않는다. 허가된 로컬 인계 자료가 있으면 ZIP과 manifest의 해시부터 대조하고, 새 경로·포함 런타임·공식 계정 연결을 확인한다. 인증 폴더를 공유하지 않는다.
4. 실제 추가 연구는 새 사용자 지시와 한도에 맞춰 실행한다. 코드 변경만으로 새 모델 요청 권한을 만들지 않는다. 입력되지 않은 약력·지원/이해관계·권리·저자 승인을 대신 채우지 않는다.

연구 원자료·실제 원고·실행 증거·로컬 패키지는 Git에 포함하지 않는다. 마지막 실제 원고 전달 묶음은 로컬 `output/pdf/frontron-renewed-20261018/`와 같은 이름의 ZIP이며, 최신 코드 검증은 `output/playwright/research-design-20261020/`에 있다. 존재 여부와 해시는 각 PC에서 확인한다.
