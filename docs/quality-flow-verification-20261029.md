# 연구 선택과 최종 준비 흐름 보완 검증

2026-10-29. 제안한 6개 항목을 구현하고 다른 프로젝트 2개에서 제한된 실제 스킬 사용을 확인했다. 기존 프론트론 원고·평가·원자료·횟수는 유지했다. 새 앱·상태 DB·연구 자동 반복 엔진은 추가하지 않았다.

## 구현 범위

| 제안 | 변경 및 검증 |
| --- | --- |
| 판정 오류 수정 | 원고 구역·키워드·도표·선언 검사는 코드 예제를 제외한다. 프론트론에 가짜 Abstract/References 코드 예제를 추가해도 실제 초록 116단어·문헌 5개가 유지된다. Pandoc 식별을 실제 버전 배너로 검증해 Python 실행 파일은 거부한다. 공저자별 구획·순서·정확한 소속/연락처·약력 연결을 검사한다 |
| 최종 준비 상태 연결 | `finalize_submission.py check`가 기존 형식·페이지 확인·과학 평가·최종 파일·사람 확인 기록을 현재 바이트와 대조한다. 원래 보고서의 대기 상태를 덮어쓰지 않으며 새 종합 상태를 작성한다. 생성 커버레터의 정확한 최종 바이트도 승인 범위에 포함한다. 선택한 DOCX의 manuscript 역할과 선택한 review_pdf의 실제 검수 PDF 일치도 확인한다 |
| 집필 전 기여 선택 | `contribution-selection.md`에 실제 근거·가장 강한 기존 답·독자의 판단 변화로 질문 2~3개를 비교하는 간단한 예시를 추가했다. 불확실한 방향을 선택할 때 쓰는 보조 지침이며 필수 단계·추가 호출·복수 완성 원고를 요구하지 않는다 |
| 변경된 근거만 재검토 | `research_workspace.py impact`가 보존된 주장–근거 연결에서 변경/누락된 파일과 영향을 받는 주장, 사라진 원고 인용, 새 질문의 명시적 열람 대상을 표시한다. 변경 없는 검증된 연결은 재사용 대상으로 표시하지만 이전 과학 평가를 새 원고로 옮기지 않는다 |
| 실제 변환 CI 필수화 | CI에서 설치된 Pandoc의 식별을 먼저 확인한다. 실제 변환 테스트 2개는 CI에서 탐색 실패를 skip으로 처리할 수 없으며 실패한다. 로컬 선택적 실행은 유지한다 |
| 다른 프로젝트 검증 | Garak·REA의 고정 커밋과 실제 1차 문서를 읽어 질문 후보를 각 3개 비교하고 각 1개를 선택했다. 두 결과를 한 번의 독립 검토로 확인하고 종료했다. 각 저장소 코드 실행·빌드·새 실험·완성 논문·수치 평가·재평가는 수행하지 않았다 |

## 테스트와 실제 프론트론 자료

전체 테스트 **208개 통과**, `compileall`과 원본/설치본 스킬 검증기 통과. CI 환경을 명시한 실제 Pandoc 변환 관련 검사 4개도 통과했으며, 실제 실행 파일은 `pandoc 3.9`로 식별됐다. 문서 처리 외 의존성을 추가하지 않았다.

최종 준비 도구의 완전한 **합성** 입력은 기존 보고서에 남은 대기 상태와 별도로 준비 완료에 도달한다. 실제 사람의 동의·승인을 만들어 낸 결과가 아니다. 파일/선언/커버레터 변경, 잘못된 페이지, 미완성 저자 사실, 과거 원고 평가, 잘못된 파일 역할과 다른 PDF는 준비 완료로 통과하지 않는다. 실제 투고 여부는 언제나 별도이며 이 작업에서는 false다.

실제 프론트론 확인 결과는 `output/quality-flow-20261029/frontron/`에 있다.

- 기존 공식 DOCX/PDF·6페이지 PNG·형식 보고서·페이지 확인 기록을 새 작업 폴더에 복사해 사용했다. Word 출력이나 원고 집필을 다시 실행하지 않았다.
- `final-preparation-verified/`에서 실제 형식 검사와 페이지 검수 기록이 연결됐다. 저자 사실·선언·사진·현재 지침/파일 확인 및 정확한 새 파일 해시에 해당하는 과학 평가가 없어 최종 준비는 확인 대기다. 이전 평가는 원래 원고 해시에 그대로 유지한다.
- 변경 없는 주장 2개는 근거 연결을 재사용할 수 있다. 별도 격리 사본의 소스 파일에 주석을 추가했을 때 관련 주장 1개만 재검토 대상으로 바뀌었다. 보존 원자료는 바꾸지 않았다.
- 새 질문에서 명시한 주장·문헌은 변경 없는 파일이어도 해당 질문을 위한 읽기 대상으로 표시됐다. 자동 의미 판단이나 새 연구 실행은 하지 않는다.

| Garak | `31107c6fc0bfa5a4f54c839a31a438755b9550ff` | 프리셋 복원 수락·오디오 콜백 적용·역방향 저장 스냅샷을 구분하는 질문을 선택했다. Steinberg의 기존 전송 기법을 인정했다. 더 가까운 메커니즘 비교와 수명주기 가정 확인이 남아 있으며 새 알고리즘·성능·음질·투고 준비 완료를 주장하지 않는다 |
| REA | `2c7583599b9ac1c847bd77b1940930fd8d4594c7` | 재구성 의무별 증거 권한과 실제 판정 소비 경로를 질문으로 선택했다. in-toto의 digest·typed predicate와 소비자 검증 정책을 기존 답으로 인정했다. 더 넓은 검증 정책/문헌 비교와 생산 경로 확인이 남아 있다. 새로운 일반 검증 원리나 S&P 기여를 입증한 결과가 아니다 |

선정에 실제 읽은 본문은 보존된 VST3 공식 문서의 관련 구역, MCP 보안 고려사항과 in-toto Statement 문서다. 읽지 않은 연결 문서와 비교 범위를 각 기록에 명시했다. 후보 선택은 각각 1회이며 완성 원고를 여러 개 생성해 비교하지 않았다. Garak의 작업 중 변경은 채택하지 않고 Git 커밋의 원본 blob만 읽었다. REA에서는 존재하지 않는 경로와 fork/upstream 출처 차이를 그대로 기록했다.

각 사례의 `contribution-choice.md`, `design-result.json`, 원자료/원문 manifest를 보관했다. 독립 검토는 `design-forward-review.json`과 `.md`다. 이 검토의 해시·인용 확인 39개가 일치하고 사용한 사례 파일 29개가 유지됐다. 질문 선정·추가 의사결정 가치·공정한 기존 답 비교를 실제로 수행한 점은 확인했지만, 두 결과는 잠정 설계다. **완성 논문 품질, 9점 달성, 게재 가능성 또는 인과적인 품질 향상을 검증한 것으로 확대하지 않는다.**
