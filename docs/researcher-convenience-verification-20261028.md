# 연구자 편의기능 구현과 실제 검증

2026-10-28 사용자 요청에 따라 Paper Factory 스킬에 선택형 연구·편집·투고 준비 기능을 추가했다. 독립 스킬 구조를 유지하고 앱·DB·SDK·고정 연구 단계나 자동 집필 루프는 추가하지 않았다. 새 의존성도 없다. 기존 원고를 재집필하거나 과학적으로 재평가하지 않았다.

## 추가한 기능

| 기능 | 구현과 범위 |
| --- | --- |
| 연구 이어가기 | `research_workspace.py checkpoint/resume`: 명시한 자료와 질문·결정·다음 작업·제약·과거 횟수를 상대 경로/해시로 보존하고 다른 위치에서 읽기 전용 검증 |
| 주장–근거 연결 | 같은 도구의 `evidence`: 실제 원고 문장·소스 행·정확 인용·선택한 원본 해시를 대조. 인용 일치가 주장 진실이나 실험 수행의 증명은 아님 |
| 개정 비교 | `compare`: 전후 원고의 정확한 diff·제목/인용/표 구조·해시를 기록. 품질 향상이나 새 점수를 추정하지 않음 |
| 참고문헌·편집 점검 | `editorial_checks.py`: 인용/참고문헌 누락·중복, DOI/URL 구문/중복, 제공한 메타데이터 차이, 표/그림 참조, 제목 중복과 약어 정의 제안 |
| 저자·공저자 | `submission_support.py authors`: 선택한 프로필의 저자 순서·교신저자·소속·연락처·ORCID·약력·기여를 새 원고/별도 저자 정보에 반영하고 누락 항목 표시 |
| 익명 초안 | `authors --anonymous`: 저자란/약력을 제거한 별도 Markdown과 잔여 식별자 점검. 완전한 익명화 인증은 하지 않음 |
| 파일 메타데이터 점검 | `metadata`: 실제 DOCX core/custom 속성·주석·변경 추적·기록 작성자 및 PDF 공개 메타데이터 필드를 읽고 선택한 저자 식별자와 대조. 원본을 제거/수정하지 않음 |
| 심사 답변 | `responses`: 실제 의견과 작성한 답변·상태·수정 인용을 결속하고 답변서 초안 생성. 미해결/변경 안 함을 유지 |
| 투고 파일 묶음 | `bundle`: 명시한 파일만 새 폴더로 복사하고 해시·체크리스트·제공한 커버레터 초안과 선언을 보존. 승인·접수는 추정하지 않음 |
| 투고처 적합성 | 스킬 지침에 집필 전 독자·논문 유형·근거 있는 기여·필요한 근거·최신 규정의 빈틈을 설명하도록 반영. 임의 점수나 자동 합격 판정을 추가하지 않음 |

일부 검사는 한정된 Markdown 관례와 휴리스틱이다. DOI 외부 조회·철회 여부·논문 신원은 이 오프라인 도구가 검증하지 않는다. 에이전트가 실제 1차 자료와 비교해야 한다. 익명 초안은 자기 인용·소스 URL·이미지·파일명·PDF XMP/주석까지 자동으로 제거하지 않는다. 실제 페이지·메타데이터 보고서와 투고처 요건을 따로 확인한다.

## 프론트론 실제 자료로 실행

이전 저장소 밖의 임시 폴더에 스킬과 선택한 입력을 복사하고 `PYTHONPATH`·`PAPER_FACTORY_ROOT` 없이 공용 Python으로 실행했다. 실제 결과는 `output/researcher-convenience-frontron-20261028/`다.

- 자료18개를 `continuation/`에 묶고 다른 위치로 복사해 `resume` 해시 검증을 통과했다. 같은 원고·이전/현재 평가·공식 출력·모든 소스161개를 포함하는 보충 ZIP·확보한 1차 문헌·핵심 소스 파일을 명시적으로 선택했다. 전체 앱 기록의 완전한 백업으로 표현하지 않는다.
- 원고의 주장2개와 소스 인용8개의 실제 문장·행·해시가 일치했다. 기존 2026-10-27/28 원고의 개정 diff를 기록했다.

- 이전에 제공된 공개 이름·ORCID만 담은 프로필을 재사용했다. 누락 소속·이메일·약력·교신저자·연구비·이해충돌 선언은 입력 대기로 남겼다. 새 현직/승인/기여를 만들지 않았다. 이 프로필의 새 저자란은 기존과 같아 해당 원고 바이트도 같았다.
- 보존된 실제 AI 심사의 의견3개로 답변서 초안을 만들었다. 두 수정 문장의 위치를 확인했고 추가 사례/효과 연구 요청은 `not_changed`로 남겼다. 학술지 리뷰어 의견이나 새 심사로 표시하지 않았다.
- 익명 Markdown을 따로 만들고 잔여 알려진 식별자를 검사했다. 원고 본문·자기 인용 등의 추가 사람 검토는 필요하다.
- 실제 원본 DOCX/PDF의 메타데이터를 읽었다. 알려진 저자 값의 메타데이터 일치와 DOCX 주석/추적 변경은0개였지만 완전 익명을 주장하지 않았다. 원고 본문의 저자란은 별도다.

## 검사와 독립 점검

최종 **130개 테스트가 통과**했다. 기존64개에 이어가기/이동·변조·정확 인용·경로 제한·diff21개, 편집19개, 저자/답변/묶음/실제 DOCX·PDF 메타데이터26개를 추가했다. 경로 탈출·링크·덮어쓰기·누락·변조·과거 횟수 보존·잘못된 인용·다중 저자 순서·메타데이터 원본 보존을 검사한다.

별도 에이전트는 초기 동결 사본에서26회 CLI 호출(도움말11회·실행/경계 확인15회)로 실제 작업을 검증했다. 입력23개와 스킬 파일 해시가 그대로였으며 구체적인 결함을 발견하지 못했다. 없는 근거·변조된 이어가기·누락된 답변 인용·경로 탈출·기존 출력 재사용의 결과도 확인했다. 답변 도구의 종료0은 보고서 작성 성공이며, 누락 인용은 보고서의 `issues`와 일치 여부를 반드시 읽어야 한다. 이를 지침에 명시했다.

이 독립 점검은 이후 추가한 메타데이터 명령을 포함하지 않는다. 해당 명령은 실제 유효 PDF fixture와 DOCX 속성/주석/추적 변경 fixture, 실제 프론트론 DOCX/PDF에 대한 루트 실행으로 따로 검증했다. 독립 점검을 전체 과학 심사나 모든 기능의 완전성 보장으로 확대하지 않는다. 메타데이터 명령 외의 핵심 코드 변경은 없고 문서만 실제 범위에 맞게 보완했다.
