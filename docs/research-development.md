# 연구 설계와 근거 보완

이 단계는 질문 후보를 비교하고 실제 가까운 방법을 읽은 다음, 독자에게 필요한 결정과 그 결정을 뒷받침할 분석을 완성한다. 단순한 저장소 설명이나 같은 원고의 재평가로 연구 보완을 대신하지 않는다. 같은 연구의 원자료·원고·심사·실패·횟수를 유지한다. 현재 지원 매체는 IEEE Software와 IEEE Security & Privacy다.

2026-10-20의 변경은 연구 설계 코드와 합성 자료의 전체 흐름을 검증한 것이다. 기존 Frontron의 실제 추가 요청·원고 생성·재심사는 하지 않았다. 기존 결과가 9점이나 투고 권고 수준으로 개선됐다는 뜻이 아니다.

## 고정된 순서와 한도

사용자가 **연구 설계·근거 보완 (최대 6회)**를 선택하면 같은 연구에 한 번만 추가 한도를 부여한다. 기존 예약 수에 6을 더하며, 예약·실패·중단·거절도 사용량에 포함한다. 이전 정책과 보고서, 예산 사용은 새 이력과 함께 보존한다. 일반 재개나 중복 클릭은 한도를 다시 부여하지 않는다.

새로 명시적으로 시작하는 보완 회차는 contract 3을 사용한다. 종료된 contract 1·2 회차와 원래 응답·거절·점수·한도는 그대로 유지하며 새 계약으로 변환하지 않는다. 일반 조회·재개는 보완 회차나 예산을 만들지 않는다. 기존 Frontron round2는 SDK35·예약24/24·심사10·종료 상태이며 이번 코드 변경으로 다시 실행하지 않는다.

1. **질문 후보와 필요한 근거 설계**: 실제 읽은 소스를 바탕으로 서로 다른 질문 2~3개를 만든다. 각 질문에 독자 결정, 가까운 기존 접근, 예상 추가 가치, 그 추가 가치를 반박할 조건, 필요한 근거와 구체적인 문헌 검색어를 적는다. 이때 선택은 잠정적이다.
2. **앱이 실제 원문 확보**: 모델이 낸 검색 계획을 기존 문헌 수집기로 실행한다. 최초 검색어는 최대4개, 수집 결과는 최대6개다. 기존 원문은 재사용하고 새로 확보한 완전한 본문·출처 증명·해시를 보존한다. 이 단계에는 추가 모델 요청이 없다.
3. **질문 선정과 비교·근거 완성**: 확보한 실제 소스와 문헌을 보고 원래 후보 전부를 선택·보류·근거 부족으로 설명한다. 가장 가까운 방법이 이미 제공하는 판단, 같은 조건의 실제 차이, 완료한 결과·반례·비용·적용 조건을 작성한다. 질문에 답하는 비교표·분석 결과를 이 요청에서 완성한다. 처음 예상했던 질문보다 다른 질문이 타당하면 선택을 바꾼다.
4. **필요할 때 한 번 내용 강화**: 확보 가능한 근거의 구체적인 빈틈이 있으면 새 검색어 최대2개로 한 번 추가 수집한 뒤, 실제 비교·결정 절차·분석 결과를 보완한다. 소스의 추가 읽기나 분석만 필요한 경우 문헌을 더 찾지 않아도 된다. 이전과 이후의 질문·발견·가까운 방법 비교·산출물 차이를 남긴다. 획득 실패나 남은 빈틈을 숨기지 않으며 두 번째 강화는 없다.
5. **독립 방법 검토**: 최종으로 완성한 현재 근거의 정확한 SHA에 대해 질문의 유용성, 기존 방법 대비 실제 추가 판단, 소스·가정과의 대응, 비교·반례·한계를 독립 검토한다. 단순히 형식이나 참조가 맞는지 확인하는 절차로 대신하지 않는다. 이 검토 뒤 새 보완 루프를 만들지 않는다.
6. **집필과 독립 평가**: 현재 근거에 대한 감사가 집필 가능으로 판단하고 수정 요구가 없을 때 두 매체 원고를 한 요청으로 쓰고 공식 Word/PDF 템플릿을 적용한다. 이어서 정확한 새 원고를 별도 한 요청으로 평가한다. 9개 항목 각각9점과 실제 투고 권고는 별도로 판단한다.

모델 요청은 질문→설계→독립 검토→집필→평가의 **기본5회**, 내용 강화를 포함하면 **최대6회**다. 원문 수집은 이 모델 횟수와 구별하며 최초·후속 수집을 합쳐 PDF 접근 예약은2회다. 실패·중단은 원래 기록과 사용량을 유지하고 같은 획득을 자동 재전송하지 않는다. 선택할 질문이 없거나 집필 준비가 부족하면 완료한 연구 보고서와 정확한 한계를 남기고 종료한다. 원고와 독립 평가를 모두 완료할 예산이 없으면 집필하지 않는다. 점수가 낮더라도 자동 재집필·재채점을 하지 않는다.

## 첫 원고부터 만드는 연구 작업

새 저장소 연구는 기존 문헌 계획 요청에서 `research_agenda`로 질문 후보와 근거 확보 계획을 함께 만든다. 별도 모델 단계를 늘리지 않는다. 실제 수집을 마친 공통 분석에서 `research_design`으로 모든 후보의 선정·보류 이유와 실제 가까운 방법을 비교하고 `work_products`를 완성한다. 이미 수집한 학술 본문을 근거로 최초 가설을 기각하거나 더 답할 수 있는 질문으로 바꿀 수 있다.

분석 원본에는 실제 소스와 제안 설계의 대응, 같은 요구 조건에서의 대안 비교표, 기존 방법이 이미 알려 주는 판단과 추가 분석이 바꾼 판단을 보존한다. 일반 저장소는 `source_comparison`을 기본으로 쓰며 무관한 보안 프로토콜을 강요하지 않는다. 유한 모형은 선택한 질문이 실제 시간·권한·절차의 문제일 때만 쓴다. 유한 사례 없이도 완전한 소스 비교·근거 검토·집필이 가능하다.

집필과 심사는 실제 선택 질문, 가까운 방법의 정확한 인용, 완료한 발견과 비교 산출물을 `writer_brief`로 전달받는다. 질문에 넣었던 예상 기여가 아니라 실제 확보·분석한 결과를 중심으로 쓴다. 새 문헌은 현재 자료 입력뿐 아니라 원고 수락·참고문헌 생성·공식 출력에서도 같은 원문 ID와 해시로 연결한다. 네이티브 비교 보고서와 연구 설계 보고서는 분석 원본에 함께 동결하고 전체 본문·SHA·읽기 증빙으로 전달한다.

구체적인 프로토콜 연구는 `typed_protocol`을 사용한다. 요청 ID와 경로·자원 ID를 구별하고, 같은 자원에 대한 서로 다른 요청을 포함한다. 허용된 거절·요청 보존·최신 상태 병합을 공통 작업과 요구사항으로 비교한다. 실제 구현 대응표와 구체적인 제안 알고리즘은 주체가 소유하는 상태, 확인·대기 가능 지점·불가역적 시작·완료·실패를 연결한다. 원자성이 입증되지 않으면 중간 환경 변경을 허용하고 한계를 남긴다.

작업 산출물의 참조·비교표·단계 연결 검사는 내부 일관성 검사다. 실제 구현의 정확성, 실무 효과나 게재 가치를 입증한 것으로 취급하지 않으며 독립 심사가 내용과 추가 기여를 판단한다. 9점 목표 충족도 오류 부재와 모든 점수뿐 아니라 실제 `consider_submission` 권고를 요구한다.

`coalesce_latest`라는 이름이나 허용된 병합 목록만으로 실제 규칙이 병합·명시적 거절을 수행한다고 입증되지 않는다. 독립 감사가 실제 guard/effect와 실행 단계를 읽고 정책과 규칙의 의미 대응을 판단한다. 분석 후에도 기존 판단이 그대로인 결과는 허용하며 추가 결정 가치가 입증되지 않았다는 한계를 자동으로 남긴다. 문구가 다르다는 사실도 실질적인 추가 기여의 증거가 아니다.

유한 모형을 사용하는 방법 감사는 규칙·불변식·확인할 상황·대조군·조건 변화의 실제 식별자를 지칭한다. 일반 소스 비교 감사는 실제 비교표와 소스·선행 원문, 추가로 바뀐 판단을 검토하며 불필요한 프로토콜 대응 목록을 요구하지 않는다. 이전 계약의 수락 복구와 원래 거절·오류·비판·수정 요구·사용 횟수도 그대로 보존한다. 과거 감사는 새 근거의 집필 허가나 추가 예산이 아니다.

## 실제로 확보할 근거와 남는 한계

앱은 기존 문헌 수집기의 학술 출처 확인과 전문 추출을 재사용한다. 완전한 학술 HTML이나 PDF가 가까운 방법 비교의 자료가 된다. 검색 결과·제목·초록·실패 경로를 읽은 전문으로 취급하지 않는다. 확보한 원문은 원 bytes와 추출 본문, 식별 증명·SHA·수집 의도·성공/부분 실패 결과를 보존한다. 중단한 수집의 의도와 이미 남은 파일은 보존하고 다음 조회에서 네트워크를 재시도하지 않는다.

기존 방법이 이미 같은 결론을 제공하면 그 사실을 비교 결과에 쓴다. 근거가 없어 답할 수 없는 질문은 보류하고, 현재 소스와 원문으로 답할 수 있는 질문·설계 절차·조건부 결과를 선택한다. 아직 구할 수 있는 문헌·구체적인 소스 분석·대안 비교의 부족을 프로젝트의 영구적인 한계로 단정하지 않는다. 앱이 수행하지 않은 구현·사용자 연구·배포·효과 측정이 필요한 주장은 측정된 결과처럼 만들지 않는다.

## 근거의 실질적 개선

유한 모델은 불리언 선택 이력만이 아니라 실제로 구별되는 자원·수신자·세대·시각·작업 수를 표현할 수 있다. 변수의 유한한 범위와 초기 값, 조건, 동시 갱신, 불변식과 확인할 상황을 명시한다. 이미 나열한 좋은 상태만 검사하는 방식 대신 규칙에서 상태를 생성한다. 상태 공간과 전이 수에는 고정된 상한이 있다.

검사는 비교하는 대안에 같은 초기 조건과 요구 속성을 적용한다. 도달하지 않는 상황, 한 번도 적용되지 않은 규칙, 전제가 성립하지 않아 형식적으로만 참인 속성을 기록한다. 보호 조건을 제거하거나 효과를 바꾼 부정 대조에서 의도한 반례가 발생하는지, 정책 조건을 바꾸면 실제 판단 결과가 달라지는지도 계산한다. 대안이 안전해야 한다거나 기존 구현에 취약점이 있어야 한다는 결론을 강요하지 않는다.

방법 보완에서는 확보한 자료로 가능한 더 강한 분석을 먼저 시도한다. 조건 변화는 모든 대안에 같은 전제를 적용해 실제 선택 변화가 있는지 계산하며, 대조군은 이름뿐인 오류 표시가 아니라 주장한 누락·덮어쓰기 등을 표현해야 한다. 이를 입증할 수 없을 때는 주장을 줄이고 한계를 기록한다. 이전 근거 버전과 실패한 검사 결과도 보존한다.

이는 선언된 유한 모델의 분석이다. 저장소 프로그램의 실행·배포 효과·성능·사용성 실험이나 보편적인 보안 증명을 뜻하지 않는다. 규칙과 실제 소스의 대응, 환경의 가정과 누락된 행동은 별도 방법 검토의 대상이며, 검사 횟수 자체를 논문의 기여로 삼지 않는다.

## 재현과 원고

앱은 분석 입력, 실제 검사 결과, 정확한 검사기 소스, 소스 증거와 해시, 실행 안내를 재현용 동봉 자료로 만든다. 검사기는 표준 Python 라이브러리로 선언된 데이터를 다시 계산하며 Frontron이나 다른 입력 저장소 코드를 실행하지 않는다. 원고는 로컬 동봉 파일의 실제 이름을 안내한다. 공개 저장소·DOI에 게시하지 않은 자료를 공개됐다고 주장하지 않는다.

원고는 선택 질문에 답하는 완료한 결과와 가까운 방법의 공정한 비교, 적용 조건·비용·반례·실제 소스 예시를 중심으로 쓴다. 사건·권한·자원의 시간 순서가 핵심인 질문에는 간결한 절차 표를 사용한다. 일반 저장소 원고에 동일한 보안 사례나 큐 설계를 강제하지 않는다. 전체 상태 목록과 수집·심사 관리 이력은 동봉 자료에 두고 내부 감사의 집필 허가를 학술적 지지로 인용하지 않는다. 완전한 학술 원문이 `document_evidence`에 보관되어도 실제 ID·전문 SHA·정확한 인용이 일치하면 유효한 학술 근거다. 참고문헌은 앱이 생성한다.

기여 주장은 소스·문헌 증거 외에 현재 네이티브 결과에 결속된 모델·속성·대조군·조건 변화 ID를 근거로 삼을 수 있다. 이 허용 목록은 모델이 입력하는 필드가 아니라 앱이 정확한 입력·검사기·결과 해시에서 구성하는 검증 문맥이다. 미등록 ID는 계속 거부한다. 저장된 집필 응답의 이런 연결만 누락된 경우에는 원 응답·거절·횟수를 유지한 채 한 번 수락을 복구하고 남은 평가 한 번만 진행한다. 검증된 인용 ID의 구분자 표기는 원문을 복원할 수 있는 증빙과 함께 정규화하며 과학적 서술과 근거 ID를 바꾸지 않는다.

새 원고가 기존 최선 원고보다 나쁘면 이전 최선 원고를 유지한다. 새 후보와 그 평가·공식 출력은 별도로 보존해 비교할 수 있다. 저자 약력·사진·권리·동의는 [투고 흐름](submission-workflow.md)의 실제 입력과 확인으로 처리하며 AI가 대신 승인하지 않는다.
