# IEEE Software·IEEE Security & Privacy 흐름

2026-10-11 사용자가 기존 자료·횟수 전체 삭제와 Frontron 실제 앱 재실행을 명시적으로 요청했다. 이전 보존·재실행 금지 지시는 이 초기화에 대해 철회됐다. 실제 투고는 별도 저자 확인 후 진행한다.

## 현재 구현

지원 대상은 두 매체의 Feature Article이다. 설계에서 두 후보의 적합성·주장·필요 근거를 평가하고, out_of_scope 후보는 생성 대상에서 제외한다.

1. 정상 앱에서 공개 GitHub URL과 목표를 입력한다.
2. 고정한 소스·문서를 읽고 한 설계를 만든다.
3. 공식 비교 기술 문서와 가까운 문헌·매체 안내를 확보하고 공통 분석을 한 번 수행한다.
4. 적합한 매체별 실제 영문 원고를 작성한다. 중복 범용 첫 원고·심사를 생성하지 않는다.
5. 현재 Word·PDF를 먼저 출력하고 분량·초록·참고문헌·필요 시사점을 검사한다. 출력 실패 중에는 독립 평가를 예약하지 않는다.
6. 현재 원고와 완전한 자료를 독립 평가한다. `issues`에는 승인에 필요한 차단 결함만 기록하고 선택적 조언은 판단 이유에 둔다. 문서 보완 요청은 실제 현재 원고·심사 해시에 연결해 공식 본문을 확보한 뒤 국소 수정·독립 평가로 이어간다. 공통 분석을 다시 하지 않아도 재도출할 수 있는 작업은 기존 분석을 유지한다. 실제로 새 보완 작업이 있고 기록이 증가한 경우만 남은 예산 안에서 이어간다. 동일 실패 요청을 반복하지 않는다.
7. 실제 저자 정보를 저장한 뒤 매체별 **저자 정보 반영해 출력**으로 현재 Word·PDF·Markdown을 만든다. native 출력은 저자 블록만 바꾸고 과학 본문·참고문헌·원 심사·기존 출력과 집필/심사 횟수를 유지한다. 현재 원고마다 최대 3회이며 실패·중단도 보존하고 같은 완료 결속은 재생성하지 않는다. 저자 정보가 바뀌면 이전 출력을 현재본으로 선택하지 않는다.
8. 내용 평가, 출력·공식 형식, 저자·제출 확인을 따로 표시한다. 저자 정보 저장은 신원·기여·권리·최종 승인 검증이 아니며 내부 통과를 게재 확정으로 표현하지 않는다.

Software는 실무 문제·대안·선택 이유·비용·적용 조건과 세 가지 시사점에 집중한다. S&P는 실제 보안·프라이버시 문제·위협 주체·신뢰와 권한 경계·대응과 잔여 위험에 집중한다. 읽기 쉬운 고유 제목을 허용하며 Abstract와 Acknowledgments, 근거·분석·한계라는 내용 책임을 유지한다. 모든 프로젝트의 실행 실험, 새 정리, 대규모 corpus를 강제하지 않는다. 해당 근거가 필요한 주장은 근거 확보 전 보류한다.

## 형식

[IEEE Software 공식 안내](https://www.computer.org/digital-library/magazines/so/cfp-ieee-software): 본문 최대 4,200단어, 그림·표 250단어 계산, 초록 최대 150단어, 참고문헌 최대 15개, 실천적 시사점 3개. 참고문헌·저자 소개는 본문 분량에서 제외한다.

[S&P 공식 일반 CFP](https://www.computer.org/digital-library/magazines/sp/cfp-ieee-security-and-privacy)는 폭넓은 기술 독자에게 유용한 비교와 실무적 설명을 요구한다. 현재 집필 목표는 5,500단어·초록 50단어다. 연구 시작 시 동결한 catalog는 공식 수치 검증 대기 상태이며, 별도 최종 검수에서 일반 Author Information을 직접 확인한 결과와 구분한다. 2026-10-11 확인한 일반 분량·초록·참고문헌과 실제 출력 대조는 [검증 기록](standalone-verification.md)에 남겼다. 특집 주제·제출 경로를 일반 원고에 적용하지 않는다.

## 검증과 자료 보존

2026-10-11 명시적 요청에 따라 이전 연구·출력·횟수와 생성 사본·연구 ZIP을 초기화했다. 계정·연결 설정·소스·런타임·합성 검사 자료를 유지했으며 이후 생성한 새 Frontron 자료·심사·횟수를 보존한다. 해당 PC와 과거 자료에 맞춘 일회용 초기화 스크립트는 현재 배포 소스에 포함하지 않는다.

새 검증은 Windows에서 Docker 없이 숨김/offscreen Electron과 Playwright로 수행한다. 정상 UI·공식 SDK로 입력하며 수동 원고·심사·기존 연구 자료를 주입하지 않는다. 증거 디렉터리는 `output/playwright/two-magazine-fresh-20261011`이다. 실제 실행 결과는 인계·독립 앱 검증 기록에서 확인한다.
